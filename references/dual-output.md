# HTML 与 Word 双文件交付

## 同一内容 两种阅读方式

默认整理一次材料，形成一份内容 JSON，同时输出同名的 `主题.html` 和 `主题.docx`。两份均包含摘要、重点、核心表格、必要步骤、自测和有依据的纠错；不重新总结第二次，不遗漏 HTML 中折叠的内容。若增加图表，Word 同样保留该图或含义等价的可读表示，不在导出后只给某一个格式增补知识。

- HTML：离线阅读，表格适配窄屏，自测答案和附录折叠。
- Word：可编辑的真实段落与表格；自测题集中在前、参考答案在后；附录和来源完整展开。不能把网页截图、HTML 源码或改后缀的文件充作 Word。
- 用户明确指定只要某个格式时遵循；没有指定时两个格式都生成。文件名以实际主题命名，默认保存到任务可写的 `outputs/knowledge-organizer/`，回复分别提供两个链接。

## 生成

先按 [HTML 内容结构](html-output.md) 写 JSON。使用有 `python-docx` 的 Python 运行：

```bash
python3 -m pip install -r <skill目录>/requirements.txt
python3 <skill目录>/scripts/render_notes_pair.py <内容.json> <输出目录/主题>
```

第二个参数是基础文件名，不带 `.html` 或 `.docx`。例如 `outputs/knowledge-organizer/课程笔记` 会生成 `课程笔记.html` 与 `课程笔记.docx`。

在 Codex 中优先使用工作区依赖工具返回的 Python；已含 python-docx 时无需安装。其他环境安装依赖后使用自己的 Python，不硬编码作者机器的路径。

中文字体默认按系统选择：macOS 为 Hiragino Sans GB，Windows 为微软雅黑，Linux 为 Noto Sans CJK SC。可用 `--cjk-font "已安装字体名"` 指定；渲染出现空白或方框时先检查渲染器的字体目录配置，不用截图代替 Word 正文。

默认拒绝覆盖任一已存在输出；改用新名字，或在明确更新该结果时添加 `--overwrite`。两份先在内存中生成并暂存，写入失败回滚已写入文件；不能只生成一份就宣称全部完成。缺依赖或权限时保留输入内容，说明错误，修复后重试，不静默降级。

## Word 排版与校验

沿用简洁学习资料风格：黑色标题、清楚层级、正文与表格可编辑。A4 页面、足够页边距，表头浅色、边框浅灰；短状态列紧凑，解释列留足宽度。表头跨页重复，行高随内容增长，正文保留条件、单位和来源。长叙述在表外展开，避免整页塞进单元格。

生成后检查两个文件都存在且非空，DOCX 可被 Word 格式库打开，核对全部表格、核心数字、纠错、答案和来源。可用 documents 技能时遵循其文档渲染流程，把 DOCX 渲染成页图并检查每一页，修复截断、乱码、表格溢出与不合理分页。其他环境使用可用的 Word/LibreOffice 渲染工具；没有渲染能力要明示仅完成结构校验，不能声称已检查视觉效果。

HTML 按其输出说明检查，输出链接必须指向两个实际创建的文件。模型行为仍需基于材料验证，脚本测试不等于每次学习总结都正确。发布技能仅包含代码、说明与虚构示例，不上传用户原始记录或私人笔记。
