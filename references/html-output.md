# HTML 学习页

## 布局

使用 `assets/notes-template.html`：白色阅读区、浅灰背景、蓝色重点色、约 1000px 宽度、清楚的标题与表头。避免大封面、统计卡和装饰动效；首屏能看到重点。

至少一张语义正确的表格，带表头、caption。窄屏表格区域横向滚动，页面本身不溢出，长词可换行。问答和附录用原生 details 默认收起，打印时展开。影响理解的冲突和条件在主表可见，不能只藏附录。

输出 UTF-8 单文件，内嵌 CSS、系统字体，不依赖 CDN、网络字体、远程图片或脚本。外部核实来源可保留 HTTP(S) 链接，正文离线可读。输入文本须转义，不能直接执行原文中的 HTML/脚本。

## 内容要能背

笔记是拿来背和复述的，不是拿来读长文的。写内容 JSON 时逐条压掉水分：

- 一句话只讲一件事；能拆成对照的不要写成段落。
- 速览、星标、表格单元格都写短句，规则句或动词开头优先，不写背景铺陈和无关修辞。
- 同一条知识只出现一次：摘要导航，主表对照，例子负责应用，自测负责回忆。不在速览、正文和结尾重复复述。
- 材料原文不整段搬运，保留结论、条件、数字、单位与来源定位。
- 没有依据的规律、比例、稳定性排序，只写待核实或明确标注为讲师经验值，不当作定理。

## 渲染

内容 JSON 结构如下。默认按 [双格式交付](dual-output.md) 运行 `render_notes_pair.py` 同时生成 HTML 与 Word；用户明确只要 HTML 时，才单独运行 `python3 <skill目录>/scripts/render_notes.py <内容.json> <输出.html>`。默认拒绝覆盖；明确修改已有结果时用 `--overwrite`。

```json
{
  "title": "主题",
  "meta": "学习笔记 · 材料日期与覆盖范围",
  "summary": "一句话主旨",
  "highlights": ["核心结论"],
  "must_know": ["★ 必备知识点，一句话", {"title": "★ 归因", "text": "把问题分类才知道改什么"}],
  "examples": ["短实例：说明它对应哪条规则、什么时候适用"],
  "visual_memory": ["记忆图：离线守已知 → 在线找未知"],
  "sections": [
    {"title": "核心知识", "intro": "主题连接句",
     "table": {"caption": "知识对照", "columns": ["知识点", "级别", "通俗解释", "例子或标准"],
       "rows": [["概念A", "重点", "解释", "标准 [S1]"]]}}
  ],
  "questions": [{"question": "为什么？", "answer": "答案与条件"}],
  "corrections": ["原说法 → 修正：依据"],
  "supplements": [{"title": "补充", "text": "材料没讲但理解主题必需的最小知识"}],
  "uncertain_items": ["无法核实的冲突或数字"],
  "change_log": ["调整：改了什么", "补充：补了什么，为什么必须补"],
  "appendices": [{"title": "来源与纠错", "paragraphs": ["S1 · 文件名 · 实际时间戳或段落"]}],
  "sources": [{"label": "核实来源", "url": "https://example.com/document"}],
  "review": "可调整复习建议"
}
```

必需 `title`、`summary`、`sections`，至少一个主 section 包含非空表格。其他按需，不凑栏目。section/appendix 支持 `intro`、`paragraphs`、`bullets`、`steps`、`table`，appendix 默认折叠。所有字符串是纯文本，不解析 Markdown。table 为 `caption`、非空 `columns`、每行与列数匹配的 `rows`。sources 只接受 HTTP(S)。

## 星标、实例与记忆方法

- `must_know`：必备知识点，**每条以 ★ 开头**，通常 3–7 条，一条一句话，独立成立、能直接背下来。它不等价于 `highlights`：速览给的是结论清单，这里给的是必须记住的那几条。
- `examples`：抽象重点要有短实例，每条说明它对应哪条规则、什么时候适用，不是例句堆砌。
- `visual_memory`：只在确实降低记忆成本时写，一行一条线索——对照矩阵、流程图、层级树、因果链、时间线、口诀；写清“看到什么 → 记住什么”；正文里要有对应的实际图形或表格，图形用自包含内联 SVG 或表格表达，不能只放没法渲染的源码。条目里不用重复“记忆图：”前缀，页面会自动加。
- 列表项（`questions` 除外）支持字符串，也支持对象：`{"title": "...", "text": "..."}`（`label`/`name` 与 `content`/`detail` 亦可），对象渲染为“标题：正文”。

## 生成后必须写变更说明

`change_log` 描述本次输出相对原材料的变化，按「调整 / 补充 / 可视化 / 精简 / 待核实」分组，一条一行：

- 调整：修正了哪些术语、事实、算术或逻辑
- 补充：补了哪些材料遗漏的知识点，为什么必须补
- 可视化：新增了哪些记忆图或实例
- 精简：删除或合并了哪些重复、过长、不影响理解的内容
- 待核实：还有哪些没核实，以及准备怎么核实

## 验证

检查摘要、主表、自测答案一致；`must_know` 每条都带 ★ 且两份文件相同；`corrections`、`supplements`、`uncertain_items`、`change_log` 在 HTML 与 Word 中都出现、顺序一致、内容相同。保留来源与补充标记。实际打开 HTML，检查桌面及窄屏、长文本、表格、问答折叠与附录，打印时折叠内容可读。无浏览器时说明只做结构检查。

最后分别给 HTML 和 Word 文件链接及少量收获，不另贴一篇长 Markdown。默认本地交付，不自动托管，不把用户记录提交到技能仓库。
