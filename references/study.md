# 学习模式

## 讲清知识，而不只是罗列

先找材料主问题，再组织能解释它的主题。概念可用“是什么 → 为什么/如何 → 何时适用 → 如何检查”，操作可用“目标 → 步骤 → 输入输出 → 常见失败”；不要求每点展开四段。

核心表用通俗解释区分易混概念：回答什么问题、与另一概念的区别、条件、一个小例子。例子注明原文或【补充例子】，先解释再引入缩写。公式保留符号、单位与条件，口诀不能代替定义。

可按领域、方法、架构、组件、应用等维度对照，但不要把对照关系自动画成严格包含关系或必经路线。类比只帮助理解。

## 证据与纠错

正文用修正后知识，附录留纠正轨迹。讲师建议、经验估计与补充分别标明。缺薪资单位、模型版本或平台名称时不能猜补。参考总结的结论同样需要核实，不能因排版精美而提升可信度。

影响理解的误区在主表旁简短提醒，原片段、修正与依据集中到折叠表；同类术语错识合并。避免将模型机制或平台操作泛化为所有系统都成立的规则。

## 主动回忆与拓展

- 默认围绕重点生成 3–5 题，短材料更少；一题一个具体问题。
- HTML 使用 details/summary，答案默认收起。至少一题解释区别、条件或迁移应用，应用题标【补充练习】。
- 答案与正文使用同一修正结果；待确认观点不能作为标准答案。
- 不强制再生成面试话术或一句话收尾来重复正文；用户要求时再增加。
- 复习节奏用一句可调整建议即可，不必做额外表格。
- 拓展只补重点缺少的前置知识、易混概念或一个应用，标【补充解释】，说明帮助哪个重点；放对应折叠区，已讲清则省略。
