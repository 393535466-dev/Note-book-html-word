# 会议模式

## 会议记录结构

先提炼议题与状态：已决定 / 建议或备选 / 未决。只有记录明确确认的决定才写为决策；多个不同意见并列保留。不要用“大家一致认为”概括未经确认的个人发言。

决策表：议题 / 已确认决策 / 依据或约束 / 来源。
行动表：行动项 / 负责人 / 截止时间 / 验收或交付物 / 依赖与状态 / 来源。
缺失字段填“未指定/待确认”，不要补人物、日期、金额或指标。负责人在记录中只是被提议时，写“拟议负责人，未确认”。没有真实行动项时不要编造任务凑表。

对数字冲突先核对口径、时间段、单位和计算。如果记录仍不能解决，保留双方数据并写需要谁/什么证据确认；不得取平均值当最终事实。语病和转写问题可以修正，但保留可能改变业务含义的术语。

## 记忆与发散

用 3–5 个回忆提示回顾“决定了什么 / 谁负责什么 / 截止日 / 风险或未决项”，题量随记录调整；答案不得为缺失字段填值。

只拓展执行所需的概念定义、依赖说明、验证方法或风险检查；标【建议】或【补充解释】。例如会议提到转化率但没有定义，可解释应先确认事件、分母和时间窗口；不能把自选口径写为已批准口径。

相对日期：有会议基准日期时可以解析，并同时保留原词；没有时写“下周五（会议日期未提供，待确认）”。
