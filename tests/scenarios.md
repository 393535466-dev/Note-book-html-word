# 行为验收场景

这些场景用于人工试用检查，不声称已运行模型自动评测。将输入交给 `$knowledge-organizer`，检查实际输出，而非匹配固定措辞。

| 输入场景 | 应观察到的行为 |
| --- | --- |
| 只说“帮我整理课堂笔记”，没有材料 | 请求提供材料，不生成虚构课堂笔记 |
| 输入学习示例 | 修正平均速度的分子；往返案例结果正确；卡片与正文一致 |
| 输入会议示例 | 保留两个数字与交期冲突；短信方案未被写成已确认决议 |
| 没有数值，却要求生成柱状图 | 说明缺乏数值依据，提供适合的概念图或先请求数值，不捏造权重 |
| 会议写“下周五”，缺会议日期 | 保留原词并标待确认，不用整理当天推算 |
| 未指定负责人或截止日 | 输出未指定/待确认，不根据发言人自行分配责任 |
| 三条极短、无错误的笔记 | 简短整理，不强行制造错误或凑齐三级与五条重点 |
| 同一材料含课堂概念与项目讨论 | 分别整理学习与会议内容；练习不误判为会议决策 |
| 用户修正一个公式或决策 | 同步更新摘要、表格、图与记忆卡，避免旧答案残留 |
| 用户要求只生成对照表 | 遵循指定格式，不机械输出默认全部栏目 |

图表脚本另由 `test_chart.py` 验证数值、比例、负数、全零、XML 转义和无效输入处理。

## HTML 与简洁表达

| 输入场景 | 应观察到的行为 |
| --- | --- |
| 一小时转写，含术语错识和大量闲聊 | 有主线与核心表，不逐段复述；同类术语合并纠错，闲聊省略 |
| 未指定输出格式 | 生成真实 HTML 文件并返回链接，不另贴整篇 Markdown |
| 参考总结有未经核实的效果比例或排序 | 借鉴布局，不直接复制为事实；自测保留条件与不确定性 |
| 同一结论多次出现 | 一个主要解释位置，不重复分级表、正文和速记 |
| 核心数字冲突 | 主表直接标待确认，不能只藏附录 |
| 手机上阅读、点击问答、浏览器打印 | 页面不横向溢出，表格单独可滚动；点击展开答案；打印含答案 |
| 用户要求只输出 Markdown 对照表 | 遵循用户格式，不强制 HTML |

## 双格式交付

| 输入场景 | 应观察到的行为 |
| --- | --- |
| 未指定输出格式 | 同时返回真实 HTML 与可编辑 DOCX 文件链接 |
| HTML 中有折叠答案和来源附录 | Word 自测题与答案分开，附录完整展开，内容不遗漏 |
| 两个文件导出后核对 | 核心数字、表格、条件、来源和纠错完全一致 |
| Word 生成失败或任一目标文件已存在 | 明示错误，不静默只交 HTML，不覆盖旧文件 |
| 表格跨页 | 表头重复，没有文字截断；逐页渲染检查 |
| 用户明确只要 HTML | 遵循指定格式，允许单独 HTML 导出 |
